# 记忆链 MemoryChain · TauriTavern 扩展

按实体召回的**情景记忆**：只把"当前这一章"与"命中实体的往事"送进上下文，其余全部折叠落盘。
解决长对话把上下文吃满、人物与旧事被挤出上下文的问题。

- 版本：1.1.0
- 适用：TauriTavern（也兼容 SillyTavern 前端的第三方扩展机制）
- 纯前端扩展：无后端依赖、无网络请求、不执行任何远程代码

---

## 一、安装（TauriTavern）

### 方式 A：直接放文件夹（最快，推荐）

把本文件夹整个复制到下面任一个目录，然后**重启 TauriTavern**：

| 作用域 | 路径 |
| --- | --- |
| 仅当前用户（local，优先级高） | `data/default-user/extensions/memory-chain/` |
| 全局（global） | `data/extensions/third-party/memory-chain/` |

> 注意：local 与 global 同名时以 local 为准；目录名与扩展名不必一致，但建议保持 `memory-chain`。

### 方式 B：用扩展面板的 Git 安装

TauriTavern 的扩展安装只接受**匿名 http(s) Git 地址**（ZIP/REST 安装已被移除）。做法：

1. 把本文件夹的内容放到一个 Git 仓库的**根目录**（仓库根必须直接含 `manifest.json`，否则安装前校验会失败）；
2. 推到 GitHub / Gitee 等可匿名访问的地址；
3. 扩展面板 → 安装扩展 → 填入仓库地址（可带 `#分支` 或 `#tag`）。

---

## 二、首次配置（3 步）

1. **导入世界书 JSON**：面板 → 「世界书 JSON」→ 选 `今山 6.json`。
   自动构建实体表：`comment` = 实体名，`key[]` = 别名；过泛的通用词与停用词自动丢弃（实测：201 实体 / 881 别名 / 过滤 42 条）。
   **词表会随记忆一起持久化**，重启后不需要重新导入。
2. **补写手动别名**（多称呼的人物务必补）：
   ```
   苓公子 => 茯苓
   宵塔主 => 茯宵
   小满 => 配角 泉小满
   ```
   每行「别名 => 实体名」，点「保存别名」。
3. 正常聊天即可；也可立刻点「记录本章」手动成章。

## 三、存储（TauriTavern 原生）

扩展会自动按优先级选择后端：

| 优先级 | 后端 | 落盘位置 |
| --- | --- | --- |
| 1 | **TauriTavern 原生 store**（`window.__TAURITAVERN__.api.extension.store`） | `data_root/_tauritavern/extension-store/memory-chain/` |
| 2 | IndexedDB（普通浏览器 / SillyTavern） | 浏览器本地库 `memoryChain` |
| 3 | 内存（不可持久化，面板会黄字提示） | 本次会话有效 |

在 TauriTavern 上的实际文件布局：

```
_tauritavern/extension-store/memory-chain/
  kv/main/<聊天哈希>.settings.json        # 每条记忆链的参数
  kv/main/<聊天哈希>.manualAliases.json   # 手动别名
  kv/main/<聊天哈希>.lexicon.json         # 世界书词表（实体 + 别名）
  kv/main/<聊天哈希>.meta.json            # 分块索引与统计
  kv/cards.<聊天哈希>/chunk0001.json      # 章节卡，每 100 章一个文件
  kv/cards.<聊天哈希>/chunk0002.json
```

分块写入的用意：写一章只重写一个分块（≤100 卡），读一整条记忆链只需读 `分块数 + 4` 个文件。
记忆按 **角色 + 存档** 隔离（命名空间 = 角色名 + chat id 的哈希），换档即换链，互不污染。

## 四、工作机制

```
用户消息
  ├─ 热区：最近 4 轮原文（每条约 800 字截尾）        ← 模型只看这一段
  ├─ Aho–Corasick 扫描 → 命中实体（O(文本长度)，与词表规模无关）
  ├─ 倒排索引：实体 → 章节卡（每实体上限 3 张）
  ├─ 打分：0.45·相关性 + 0.30·λ^Δ章 + 0.15·log频次 + 0.20·类型 − 0.10·长度
  ├─ min-max 归一化 → 排序 → 预算内裁剪（放不下就降级为摘要）
  ├─ 三态：≤6 章 → 完整；被点名 → 摘要（复活）；≤30 章 → 摘要；更老 → 隐藏
  └─ setExtensionPrompt（对话内 @深度 2）
```

写入侧（不在关键路径）：每 8 轮或点「记录本章」→ `generateQuietPrompt(skipWIAN)` 让**便宜模型**输出 JSON 章节卡 → 入索引 + 落盘。摘要失败自动退回"粗记"。

## 五、性能（node 桩环境实测）

| 项目 | 结果 |
| --- | --- |
| 词表构建（201 实体 / 881 别名） | **9.5 ms**（一次性，且会持久化） |
| 单次召回（59 章） | **0.023 ms** |
| 单次召回（5000 章） | **0.024 ms** |
| 写入并索引 5000 章 | **33 ms** |
| 单次注入量 | 554 字（预算 1200，硬顶生效） |

关键点：扫描成本只与文本长度相关；索引全内存，每轮 **0 次 I/O**；只对命中实体算分；同一消息结果有缓存；落盘按分块增量写。

## 六、参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 启用 | 开 | 关闭时立刻清空注入 |
| 注入预算（字） | 1200 | **硬上限**；建议 800–1500 |
| 热区轮数 | 4 | 参与实体识别的最近消息数 |
| 时间衰减 λ | 0.85 | 每章保留比例，越小越健忘 |
| 完整注入（章内） | 6 | 距今 ≤ 6 章 → 完整卡 |
| 摘要注入（章内） | 30 | 距今 ≤ 30 章 → 一行；更老则隐藏 |
| 每实体最多卡片 | 3 | 防止一个人带出十条往事 |
| 自动成章（轮） | 8 | 0 = 关闭，改手动 |
| 用模型生成章节卡 | 开 | 关闭则"粗记"，零模型成本 |
| 注入位置 / 深度 | 对话内 / 2 | 亦可改为提示词内或之前 |
| 通用词阈值 | 3 | 某关键词出现在 > 3 个条目里即丢弃 |

## 七、排错

| 现象 | 处理 |
| --- | --- |
| 面板黄字"仅内存" | 说明两种持久化后端都不可用；检查是否用了隐私窗口/受限 WebView |
| 一直没有注入 | ① 导入过世界书 JSON？② 已有章节卡？③ 打开「调试日志」看控制台 `[记忆链]` |
| 重启后实体表为空 | 1.1.0 起已随记忆持久化；若为空请重新导入一次世界书 |
| 注入太啰嗦 | 预算降到 800、"完整注入"改 3、每实体卡片改 2 |
| 该带出的旧事没带出 | 补该人物的手动别名，或调大"摘要注入（章内）" |
| 章节切得太碎 | "自动成章"从 8 调到 12–16 |
| 摘要质量差 | 给 quiet prompt 换便宜但中文强的模型；或关掉自动摘要改手动 |
